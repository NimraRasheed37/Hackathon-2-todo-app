# Implementation Plan: AI-Powered Todo Chatbot (Phase 3)

**Branch**: `003-ai-chatbot` | **Date**: 2026-02-02 | **Spec**: [spec.md](./spec.md)

## Summary

Phase 3 adds an AI-powered chatbot interface to the existing Phase 2 Todo application. Users can manage tasks through natural language conversation using OpenAI's gpt-4o-mini model. The implementation uses direct Python tool functions (not a separate MCP server) for task operations, with conversation persistence in PostgreSQL.

## Technical Context

**Language/Version**: Python 3.11 (backend), TypeScript/Next.js 16 (frontend)
**Primary Dependencies**: FastAPI, SQLModel, OpenAI SDK, React 19
**Storage**: PostgreSQL (Neon) - existing + 2 new tables
**Testing**: pytest (backend), manual testing (frontend MVP)
**Target Platform**: Railway (backend), Vercel (frontend)
**Project Type**: Web application (frontend + backend)
**Performance Goals**: <5s total response time, <100ms tool execution
**Constraints**: 50 message context limit, user isolation required
**Scale/Scope**: Single-tenant per request, stateless backend

## Architecture Decisions

### AD-001: Direct Tool Functions vs MCP Server

**Decision**: Implement tools as direct async Python functions, not separate MCP server

**Rationale**:
- Simpler architecture, single process
- Direct database access without HTTP overhead
- Easier testing and debugging
- MCP is designed for multi-agent orchestration (overkill here)

**Trade-offs**:
- Less flexibility if we need external tool servers later
- Tight coupling between tools and backend

### AD-002: Conversation Storage in PostgreSQL

**Decision**: Store conversations and messages in PostgreSQL using SQLModel

**Rationale**:
- Consistent with existing data layer
- Supports complex queries and persistence
- Automatic relationship handling

**Trade-offs**:
- Slightly more latency vs Redis
- Requires schema migration

### AD-003: 50 Message Context Limit

**Decision**: Load only last 50 messages for OpenAI context

**Rationale**:
- gpt-4o-mini has 128k context, but cost increases with tokens
- 50 messages ≈ 10-15k tokens (safe buffer)
- Maintains conversation coherence

**Trade-offs**:
- User loses access to very old context
- May need summarization in future

### AD-004: Request-Response vs WebSocket

**Decision**: Use standard HTTP request-response for chat

**Rationale**:
- Simpler implementation
- No real-time requirements
- Matches OpenAI's API pattern

**Trade-offs**:
- No streaming responses (future enhancement)
- Polling needed for long operations
